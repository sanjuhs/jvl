Compile the law into a program you can check.

JVL turns a contract or a case file into a small program. Facts carry their source. Propositions carry a confidence. And legal arguments type-check.

Try it live → Learn the language

The graph stores what the case says. The JVL program determines what follows from it.

loan-vs-investment.jvl
jurisdiction IN.Contract.v1

party A = Person "Anil Kumar"
party B = Person "Beena Rao"

fact transfer_17 : TransferOfValue {
    from:   A
    to:     B
    amount: INR 1_000_000
    on:     2025-03-10
} from source(doc="BankStatement_3", page=2, para=4) status Established

claim c_loan by A : "the transfer was a loan"
    asserts Loan(transfer_17)

evidence w17 : Message { author: B  text: "I'll repay next month." }
    from source(doc="WhatsApp_17", para=21)
    supports RepaymentObligation(transfer_17)

rule loan_definition:
    Loan(t) requires TransferOfValue(t) RepaymentObligation(t)

assert Loan(transfer_17) under BalanceOfProbabilities
Why it's different

Three ideas no other legal DSL combines

Most tools extract JSON (silent on what follows) or build a graph (vague on meaning). JVL adds the executable meaning layer — and keeps the other two underneath it.

⚖️

Epistemic status is a type

A proposition is never just true. It's Proven, Supported, Disputed, Unsupported, Refuted, or Unknown — judged against a standard of proof. Law lives in doubt; the type system lives there too.

🔗

Provenance is mandatory

Every fact links back to doc / page / paragraph / exhibit. A conclusion the compiler can't trace to the record is a defect it reports — the guardrail against a proof of a hallucinated fact.

✅

Arguments type-check

assert Cheating(x) returns a derivation trace — which elements hold, which are missing, which are contested — not a bare yes/no. Static type checking for a legal argument.

The stack

The program is the data layer

JVL sits on top of extraction and graphs — and can emit both. One program holds the facts, the relationships, the provenance, and the logic, and it can compute over all of it.

  • jvl emit json — deterministic canonical data
  • jvl emit graph — nodes & edges of the case
  • Ask questions and get sourced, deterministic answers

Compare & verify

Do two contracts mean the same thing?

Turn both documents into programs, then ask. equiv compares what each contract concludes and its operative terms — ignoring ordering, comments, and cosmetics — and names exactly where they diverge. diff gives the full delta.

  • Version a contract and see the semantic change, not the text noise
  • Check a document against a reference template
  • Machine-readable output for pipelines (--json)
What you can do

One program, many questions

jvl check

Parse, type-check, and audit every fact for provenance.

jvl assert

Does a proposition hold, to a standard of proof? With a full trace.

jvl explain

The derivation tree for any proposition, sourced to the record.

jvl discover

Which elements of a claim are still missing? The gap, pinpointed.

jvl check-contradictions

Where do the clauses conflict with each other?

jvl constraints

Objective money / date / number checks — pure, non-arguable arithmetic.

jvl simulate --without X

Counterfactual: drop an exhibit or a rule and re-run.

jvl diff · equiv

Compare two versions — structurally and semantically.

jvl emit json · graph

The program as data — it can be the JSON/graph layer.

jvl ask "…"

Ask in plain English; the engine computes the answer.

jvl fmt

Canonical formatter — round-trip safe, clean diffs.

jvl check --audit

Flag any supported conclusion that traces to no source.

The central thesis

The LLM transforms. The program decides.

An LLM is an unreliable judge but a capable translator. So JVL never asks it to weigh whether a fact is legally valid. It asks only for a faithful translation: document → program, question → assertion. Then the assertion runs against the whole logic of the program, and the deterministic engine — not the model — returns the answer, with a trace back to the record.

🤖

What the LLM does

  • Read a messy document — any length
  • Emit a JVL program with honest sources
  • Map a natural-language question to an assertion

Fuzzy, linguistic, error-prone — and checkable, because the compiler rejects what doesn't parse or cite.

⚙️

What the program does

  • Run the assertion over every rule and fact
  • Return proven / refuted / disputed — deterministically
  • Show the derivation, sourced to the document

Exact, reproducible, auditable — the judgement lives in code you can read, not in a black box.

Scale is the point. A program can be arbitrarily large — a whole contract, a constitution, a treatise compressed into thousands of typed propositions and rules. However big it gets, an assertion still runs over all of it, and the compiler can still ask: is this consistent? is this clause violated? does this conclusion follow? That is a question you cannot ask natural language at all.
